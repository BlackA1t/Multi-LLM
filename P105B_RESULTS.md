# Multi-LLM — P1.0.5B Results

Дата проверки: 2026-11-16

## Итог

P1.0.5B реализует ручной этап первого синтеза ChatGPT S1 поверх существующих SQLite, IPC v1, Native Messaging Host и Web-Chat Bridge.

- После допустимого R0 сервер создаёт одну задачу `S1_SYNTHESIS` для ChatGPT в совместимой внутренней фазе `COMPARISON`.
- Старый переход `COMPARISON → CRITIQUE` заблокирован до P1.0.5C.
- S1-пакет детерминированно собирается из оригинального prompt, восьми зафиксированных R0 и необязательного Perplexity.
- Источники идут в фиксированном порядке: ChatGPT, Gemini, DeepSeek, Qwen, Grok, Copilot, GigaChat, Алиса; Perplexity добавляется отдельно последним.
- Каждый вход фиксирует provider ID, reported model, task ID, result ID, revision, status, SHA-256 и gap reason.
- Полные ответы передаются без Python-суммаризации. Недоверенный текст сериализуется как JSON `content`, поэтому не может незаметно закрыть или подменить структурные границы пакета.
- Шаблон S1 имеет версию 1 и содержит инструкции по сравнению, критической оценке аргументов, работе с источниками, неопределённостями и формированию S1.
- Большой пакет без усечения разбивается на нумерованные prompt artifacts размером не более 512 KiB. Последняя часть содержит явную команду начать синтез только после получения всех частей.
- UI показывает полноту R0, размер и SHA пакета, список частей и прогресс копирования. Отчёт S1 импортируется прежним проверяемым chunked upload.
- Новая редакция S1 создаёт immutable response revision; `s1_result_links` связывает результат с использованным пакетом и его входами.
- При изменении входной версии package metadata получает `stale=true`; копирование устаревшего пакета блокируется.

## SQLite migration v4

Добавлены таблицы:

- `s1_packages` — версия шаблона, fingerprint входов, SHA полного логического пакета, размер, число частей и полнота R0;
- `s1_package_inputs` — неизменяемые ссылки на конкретные версии R0/Perplexity;
- `s1_package_parts` — нумерованные prompt artifacts и их SHA-256;
- `s1_result_links` — связь импортированного S1 с подготовленным пакетом.

Старые таблицы, фазы и записи не удаляются и не переименовываются. Старые COMPARISON-сессии могут подготовить новую S1-задачу через идемпотентную `s1.package.prepare`, если содержат допустимый набор R0; прежняя structural-comparison запись остаётся сохранённой, но скрыта из нового рабочего UI.

## IPC v1

Версия envelope не изменена. Добавлены операции:

- `s1.package.prepare`;
- `s1.package.get`;
- `s1.package.part.chunk`;
- `s1.package.part.copy`.

Передача частей и ответов остаётся ограниченной и проверяемой; большие значения не помещаются непосредственно в один Native Messaging response.

## Security review

- Реальные LLM/API-вызовы, OAuth и DOM-автоматизация не выполнялись.
- Сторонние ответы не исполняются и не интерпретируются Python как инструкции.
- Полные материалы не включаются в IPC-ошибки, session events или диагностические логи.
- Тесты и Native Host probe используют только синтетические данные и временные SQLite-базы.
- Пользовательская `research.db`, Chrome profiles, credentials, `.env`, токены и локальные логи не включены в Git.

## Непроверенные runtime-сценарии и ограничения

- Ручной Chrome smoke нового S1-интерфейса не выполнялся; component tests, production build и Native Host probe прошли.
- Реальный новый чат ChatGPT Plus не открывался, пакет в него не вставлялся и реальный S1 не импортировался.
- Программа не оценивает точное число токенов: отображается фактический размер UTF-8 и используется безопасное деление по байтам.
- P1.0.5C reviewers и ChatGPT S2 не реализованы; переход из S1 намеренно заблокирован.
- Если историческая COMPARISON-сессия не содержит допустимые восемь/семь R0 с сохранёнными revision records, S1 не создаётся и возвращается явная ошибка вместо ложного полного пакета.
